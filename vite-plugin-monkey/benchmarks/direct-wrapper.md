# 直接包装与模块系统分流（2026-11-06）

> 历史实验记录，描述当轮实现与测量结果，不代表当前行为或测试状态。临时源码快照已于 2026-11-07 清理，原复现命令不再可用；当前实现见 [Architecture](../ARCHITECTURE.md)。

本轮实现保留默认 JavaScript 拆分：只有一个无需模块链接的 chunk 时直接添加严格模式函数包装，存在顶层 await 或 for-await 时改用 async 包装。多 chunk，以及仍含 import、export 或 import.meta 的单 chunk，交给现有自有模块系统。

已删除 IIFE 二次构建、输出模块模拟加载器和 TLA 占位/恢复实现。最终压缩单独调用 Oxc 或用户安装的 Terser，不启动另一轮 Vite 构建。普通 CSS 的运行时帮助函数由首轮 Vite 构建处理，使 CSS 小脚本仍可直接包装。

## 同步执行验证

模块系统新增 `start()` 用于入口启动：已注册的同步模块图在当前调用栈内完成链接、依赖执行及入口执行，同步错误直接抛出。动态 `import()` 继续通过缓存 Promise 延后执行；Worker 的资源加载和含异步生成器的模块链接保持异步。

验证覆盖：

- 单 chunk、静态多 chunk 在已经排队的 microtask 前执行，压缩开关均验证。
- 两条路径中的同步初始化错误在脚本调用返回前抛出。
- 单 chunk 的顶层 await 之前立即执行，之后等待 Promise 完成。
- 保留 chunk 边界的静态循环依赖、live bindings 和异步兄弟依赖。
- 默认动态拆分、延迟执行、并发导入缓存及首次失败后的重复拒绝。
- CSS 注入先于入口执行，外部全局依赖同步可用。
- Terser 的压缩选项及同步执行行为。

含 TLA 的复杂模块图依然使用异步链接，不保证与原先平铺 async IIFE 在首个 await 之前具有相同的调用栈时机。已经被上游合并的模块边界也无法恢复；这次没有强制内联动态模块，也没有声称修复 Rolldown 的静态 TLA 合并限制。

## 体积与耗时

环境：Node 26.13.0、Vite 8.3.0、Rolldown 1.2.7、Windows x64。同进程、同临时工程，两次预热后交替执行两种实现，各采样九次，取中位数；`build.write=false`，不包含冷启动或磁盘写出成本。

下表启用压缩，体积为所有产物文件的字节总和。

| 场景             |   修改前 → 修改后 |       构建中位数 |
| ---------------- | ----------------: | ---------------: |
| 简单主脚本       |       116 → 116 B |  17.47 → 9.91 ms |
| 含 CSS 主脚本    |       360 → 360 B | 24.00 → 16.97 ms |
| 主脚本顶层 await |       146 → 145 B | 18.63 → 11.81 ms |
| 主脚本动态导入   |   4,802 → 2,406 B | 16.62 → 16.80 ms |
| 外部全局依赖     |     181 → 2,317 B | 18.37 → 11.82 ms |
| 最小内联 Worker  |  8,497 → 11,424 B | 26.91 → 20.85 ms |
| 最小资源 Worker  |  8,564 → 11,491 B | 26.03 → 20.44 ms |
| 复杂内联 Worker  | 21,075 → 24,002 B | 71.06 → 69.61 ms |
| 复杂资源 Worker  | 20,119 → 23,046 B | 53.60 → 41.80 ms |

简单脚本和 CSS 脚本分别约快 43% 和 29%，压缩体积相同。动态导入场景没有可确认的耗时收益，体积下降主要来自新增的最终整体压缩，不能归因于删除二次构建：该场景原本就使用模块系统。

Worker 主脚本仍需链接生成的 Worker 运行时模块，现在通过主线程注册表完成；Worker 内部又需要独立注册表。因此 Worker 示例增加约 2.9 KB。外部依赖小脚本也从直接 IIFE 绑定改为模块系统链接，增加约 2.1 KB。这些是本轮分流方案的实际体积代价，没有再次引入专用静态链接器消除它们。

默认 `minify: false` 时，最小内联 Worker 为 10,028 → 16,091 B，外部依赖示例为 210 → 5,362 B；简单主脚本为 125 → 125 B，CSS 为 449 → 455 B。全部未压缩数据、gzip 大小、每次采样及源码/产物哈希保存在 [direct-wrapper.json](./direct-wrapper.json)。短时基准受系统调度影响，尤其复杂 Worker 波动明显，不宜将这些比例视为所有工程的固定收益。

节点端源码维持 70 个 TypeScript 文件，非空行数从 4,750 减少到 4,552，减少 198 行（约 4.2%）。相对于本轮基线，生产源码实际 diff 为新增 169 行、删除 375 行；两种统计口径不同。
