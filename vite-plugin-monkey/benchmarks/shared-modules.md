# 共享模块转换层对比

> 历史实验记录，描述当轮实现与测量结果，不代表当前行为或测试状态。临时源码快照已于 2026-11-07 清理，原复现命令不再可用；当前实现见 [Architecture](../ARCHITECTURE.md)。

本轮将单 chunk 包装和模块注册的源码分析、Vite 导入协议适配、顶层 await 判断及模板标签调用修正集中到 `modules/transform.ts`。`modules/globals.ts` 提供共用的默认导入/命名空间 getter 兼容表达式。无导入导出的直接包装仍跳过 `moduleRunnerTransform`。

`wrap.ts` 负责将导入转成函数参数；`compile.ts` 负责模块 ID 解析和注册函数生成。两者共用转换结果格式，不合并运行时调度。输出生成器现在只返回代码，消费 chunk 的清理与 CSS grant 检测由公共输出阶段完成，CSS 注入表达式只生成一次。Worker 注入时机及模块运行时保持原有实现。

## 行为修正

重构前，同一段外部依赖代码在两条路径中存在可复现差异：

| 行为                                    | 直接包装  | 原模块系统   | 重构后模块系统 |
| --------------------------------------- | --------- | ------------ | -------------- |
| 全局属性由 1 更新为 2 后读取导入值      | 2         | 1            | 2              |
| 导入函数作模板标签调用，严格模式下 this | undefined | 命名空间对象 | undefined      |

模块系统原先复制外部属性值，现在和直接包装的命名空间兼容对象一样，通过 getter 读取原对象。标签调用在求值模板替换值之前捕获函数，并以无接收者方式转发调用；命名空间成员调用仍保留命名空间接收者。

## 产物与耗时

Node 26.13.0、Vite 8.3.0、Rolldown 1.2.7、Windows x64。同进程、同临时工程，预热两次后交替执行两个实现，各采样九次，取中位数；`build.write=false`。体积包括 userscript 元数据。

| 场景，开启压缩            | 脚本体积：之前 → 之后 | 构建中位数：之前 → 之后 |
| ------------------------- | --------------------: | ----------------------: |
| 简单主程序                |           116 → 116 B |         10.14 → 9.80 ms |
| CSS                       |           360 → 360 B |        15.78 → 15.45 ms |
| TLA                       |           145 → 145 B |        11.24 → 10.30 ms |
| 普通动态导入              |       2,406 → 2,406 B |        12.24 → 12.56 ms |
| 单 chunk 外部命名导入     |           181 → 181 B |        10.91 → 12.03 ms |
| 单 chunk 外部默认导入     |           470 → 470 B |        11.85 → 11.35 ms |
| 单 chunk 外部命名空间导入 |           462 → 462 B |        10.64 → 10.37 ms |
| 外部依赖 + 动态导入       |       2,512 → 2,726 B |        13.38 → 15.07 ms |
| 最小 inline Worker        |     11,424 → 11,424 B |        21.86 → 19.27 ms |

原有 22 个场景的完整产物哈希全部一致。新增外部依赖 + 动态导入场景的压缩脚本增加 214 B，gzip 从 1,093 增至 1,171 B，这是用实时 getter 替代属性快照的开销。关闭压缩时，该例为 5,859 → 6,193 B。测试中的模板标签调用还会按实际使用增加转发表达式；该基准例没有标签调用。

耗时有升有降，不能宣称整体加速。共享分析使模块注册路径也检查原始源码，再解析 Vite 转换结果；收益主要在于消除语义分叉和集中维护转换协议。

节点端源码非空行由 4,649 降至 4,629，文件数由 70 增至 72。没有新增依赖，也没有新增二次构建。

## 验证

- 31 个测试文件、259 项非浏览器测试通过。
- 28 项生产浏览器测试、6 项模块契约浏览器测试通过，覆盖循环依赖、动态导入、TLA 和 Worker。
- 同一组构建行为测试覆盖直接包装/模块系统以及不压缩、Oxc、Terser 三种输出。
- TypeScript、两套公开声明检查和 ESLint 检查通过；发布构建和 postbuild 通过。
- 发布入口实测两条输出路径的同步读取、属性更新、模板标签及动态导入，压缩开关均通过。

开发浏览器测试未在本轮重复执行，之前的空 CSS HMR 超时不属于本轮改动范围。这些测试不构成完整的 ECMAScript 模块一致性验证；转换仍依赖 Vite 输出的模块协议。

完整样本、产物哈希及源码哈希见 [shared-modules.json](./shared-modules.json)。基线为本轮开始前的未提交源码快照；JSON 中的 `baselineRevision` 仅表示当时 HEAD，不能用于还原已清理的快照。
