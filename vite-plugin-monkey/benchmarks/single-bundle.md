# 单文件输出原型评估（2026-11-06）

> 历史实验记录，描述当轮实现与测量结果，不代表当前行为或测试状态。临时源码快照已于 2026-11-07 清理，原复现命令不再可用；当前实现见 [Architecture](../ARCHITECTURE.md)。后续已取消 IIFE 二次构建，但仍保留默认拆分与内部模块系统。

结论：按用户决定保留现有实现，暂不切换。生产 `src/` 已按实验前快照逐文件恢复并校验一致；保留自有模块系统与 IIFE 二次构建，未恢复 Rollup 或 SystemJS 依赖。

原型强制主脚本和每个 Worker 的 `codeSplitting: false`，由 Rolldown 合并内部模块，再转换残留外部导入/导出、添加同步或 async 包装函数。删除了模块注册、链接、加载器及 IIFE 二次构建，只保留独立压缩步骤。

## 实测收益与代价

环境为 Node 26.13.0、Vite 8.3.0、Rolldown 1.2.7、Windows x64。两次预热后交替运行两个实现，各采样九次；耗时取中位数，`build.write=false`。下表均启用压缩，体积为所有输出文件字节数之和，不是 gzip 大小或运行时内存。

| 场景             | 现有体积 → 原型体积 | 现有耗时 → 原型耗时 |
| ---------------- | ------------------: | ------------------: |
| 最小内联 Worker  |     8,497 → 5,161 B |    24.34 → 18.82 ms |
| 复杂内联 Worker  |   21,075 → 13,082 B |    36.86 → 27.88 ms |
| 复杂资源 Worker  |   20,119 → 12,264 B |    38.73 → 29.35 ms |
| 主脚本动态导入   |       4,802 → 617 B |    12.25 → 12.11 ms |
| 简单主脚本       |         116 → 116 B |     14.80 → 9.28 ms |
| 含 CSS 主脚本    |         360 → 974 B |    25.48 → 17.07 ms |
| 主脚本顶层 await |         146 → 145 B |    17.88 → 11.74 ms |

`src/node` 从 70 个 TypeScript 文件、4,750 个非空行减少到 67 个文件、4,245 个非空行（减少 505 行，约 10.6%）。这是全部节点端源码的计数，不代表第三方代码或维护成本的精确计量。CSS 小脚本变大来自原型中合成模块的命名空间包装；该原型没有继续做体积优化。

完整数据、每次采样、gzip 大小及源码/产物哈希见 [single-bundle.json](./single-bundle.json)。基准来自实验开始前的未提交工作区快照，JSON 中的 `baselineRevision` 仅标识当时 HEAD，不能用该提交替代快照。测量的是原型，不是恢复后的当前实现。

## 语义验证

常规延迟执行、并发/重复成功导入、循环依赖、live bindings、动态模块顶层 await 及其拒绝传播通过。原型的现有非浏览器测试 206 项通过；生产浏览器测试 27/28 通过，剩余一项是旧断言要求存在 `chunks/` 目录；独立模块浏览器测试 6 项通过。

但更严格的模块测试有五项失败，涉及两个问题：

1. **明确的实际产物回归：动态模块同步抛错后的重复导入。** `main.js` 暴露 `() => import('./fail.js')`，`fail.js` 顶层抛出 `new Error('failure')`。现有实现两次调用都拒绝；原型第一次拒绝、第二次成功。开启和关闭压缩都能复现。模块只执行一次，但错误没有被正确保留。`undefined`、`null`、空字符串、`false` 四个抛出值也在模块测试中失败；`strictExecutionOrder: true` 没有解决。
2. **Rolldown 静态合并限制：异步依赖阻塞同步兄弟模块。** 入口先静态导入等待 gate 的模块，再导入同步兄弟模块。单文件输出在 gate 释放前只执行了等待模块；开启 `strictExecutionOrder` 结果相同。自有模块系统在保留模块边界时能执行兄弟模块，但生产构建上游也可能合并静态模块，因此这不是“当前所有构建正确、只有原型错误”的证明。

实际产物错误缓存对比及静态 await 执行顺序记录于 [single-bundle-semantics.json](./single-bundle-semantics.json)。保留的构建测试覆盖压缩开关下重复导入的失败缓存，模块单元测试覆盖循环、live bindings、异步兄弟依赖及不同抛出值。

恢复后验证：219 项非浏览器测试、28 项生产浏览器测试、6 项模块契约浏览器测试通过，TypeScript 和 ESLint 检查通过。开发浏览器测试为 8/9 通过；`test/browser/dev/style.spec.ts:77` 的空 CSS HMR 更新超时，单独复核仍失败。本轮没有修改开发模式源码或该测试；此问题保留为未解决项，没有通过跳过断言使测试变绿。

## 数据来源

实验使用当时未提交的基线和原型源码快照，现已清理。JSON 中的 `baselineRevision` 仅记录当时 HEAD，不能还原这两个快照；保留的测量结果用于历史对比。
